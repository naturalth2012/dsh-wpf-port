# 12 · UI 设计规划（Dsh.Wpf 视觉体系）

> 目的：为 Dsh.Wpf 建立**单一事实源**的视觉体系，治理当前"色板割裂、按钮堆叠、无层级、消息裸文本"的粗糙感。
> 语言基调：**OpenCode 的简洁克制** + **中国本土化的沉静雅致**（青绿/黛蓝体系、中文渲染优先、口语化专业文案）。

---

## 1. 设计原则

1. **一个品牌色，其余靠灰阶**：全界面只保留 1 个主品牌色 + 1 个危险色；层次用背景/边框/文字三级灰阶表达。
2. **中文渲染优先**：汉字不斜体、行高放宽、字号基准略大；数字/代码用等宽。
3. **克制的信息密度**：操作以图标+tooltip 为主，文字按钮只给主操作；上下文相关操作按需出现。
4. **留白与阴影代替粗边框**：面板之间用留白/柔和阴影，少用 1px 硬边。
5. **深浅主题无漏色**：所有颜色收敛为设计令牌，杜绝硬编码中间色。

## 4. 字体体系

| 用途 | 栈 | 说明 |
|---|---|---|
| UI 中文 | `Microsoft YaHei UI, 微软雅黑, Segoe UI` | 中文首选 |
| 代码/数字/路径 | `Cascadia Mono, Consolas, Courier New` | 等宽 |
| 行高 | 中文 1.6–1.7；代码 1.5 | 方块字需更大行高 |
| 字号基准 | **13px**（正文）/ 12px（辅助）/ 15px（标题）/ 18px（会话名） | 中文略大保可读 |
| 字重 | 常规 400 / 半粗 600 / 粗 700 | 不用 500 中间值 |

> 规则：**中文从不斜体**；`Italic` 仅用于英文术语/代码注释。

## 5. 控件样式层（L2）

- **按钮三级**：
  - `Primary`：品牌底 + 白字，唯一主操作（新建会话/发送/连接）。
  - `Secondary`：Surface2 底 + Border，常规操作。
  - `Ghost`：透明，hover 出浅底，工具栏/行内小操作。
  - 危险操作（删除）：Ghost 底 + Danger 红字，hover 出红浅底；**全界面最多 1 个实心红按钮**。
- **统一**：圆角 6px、聚焦环 2px 品牌色、hover 过渡 120ms、禁用 0.5 透明度。
- **输入**：Surface1 底 + Border，聚焦品牌色边框 + 柔和外环。
- **滚动条**：细（6px）、圆角、hover 才显。
- **列表项**：选中品牌浅底 + 左 3px 品牌条；hover 浅灰。

## 6. 布局架构（L3，渐进式）

当前"顶部一排按钮 + 左右分栏"。演进为：

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏：品牌名 · 连接状态胶囊   …(搜索) [新建会话] [设置]       │
├──────────┬──────────────────────────────┬───────────────────┤
│ 左栏(会话)│  中栏（对话）                │ 右栏(辅助/可折叠)   │
│ 工作区▲   │  消息流                      │ 作业/队列/轨迹/产物│
│ 会话树    │  ┌────────────────────────┐ │                   │
│          │  │ 输入框 [发送]           │ │                   │
├──────────┴──────────────────────────────┴───────────────────┤
│ 状态栏：连接 · 模型 · 统计条 · 通知                          │
└────────────────────────────────────────────────────────────┘
```

- **顶栏**只放全局动作（新建/搜索/设置）+ 品牌 + 连接状态；把"连接/断开/刷新/重命名/删除/选模型/刷新模型/诊断/深色/语言"**按上下文移到合适位置**：
  - 连接/断开 → 顶栏胶囊内或设置页。
  - 重命名/删除 → 会话右键菜单（选中会话才见）。
  - 选模型 → 顶栏模型下拉。
  - 诊断/深色/语言 → 设置页（`⚙`）。
- **右栏可折叠**：作业/队列/轨迹/产物作抽屉，主对话区可全宽。

## 7. 消息流视觉（L4）

- **角色标识**：用户 → 右侧品牌色气泡；助手 → 左侧灰气泡 + 品牌色"AI"角标；工具 → 代码块卡片；context/compacted/retry → 居中灰条小字。
- **时间戳**：hover 消息时显示。
- **操作按需**：复制/反馈/分支按钮 hover 该消息才淡入。
- **空状态**：无会话/无结果给图形占位 + 引导文案。
- **加载反馈**：连接中/流式输出呼吸指示。

## 10. 工程约束：XAML 颜色零硬编码

> 背景：`06` §132（2026-08-19）已记录"XAML 硬编码色值（`#3B82F6` 等）未收敛为设计令牌，属本文件 §1.5 原则缺口"。2026-08-21 用户实测深色模式发现"设置弹窗/作品日志/审批面板/HTML 预览"等区域不跟随主题，根因即散落硬编码 hex 与未纳入令牌的语义色。本次统一收敛。

### 10.1 硬性规则
1. **XAML 中禁止硬编码颜色字面量**：`Background="#XXXXXX"`、`Foreground="White/Black/Red/..."`、`BorderBrush="#..."` 一律改为 `DynamicResource <TokenKey>`。
2. **C# 后端禁止 `Brushes.White` / `new SolidColorBrush(Color.FromRgb(...))` 等硬编码**，改为 `Application.Current.TryFindResource("<TokenKey>")`。
3. **语义着色用专门的语义令牌**，不得复用框架灰阶或裸 hex 表达"信息/警告/危险/高亮/卡片"。

### 10.2 语义令牌清单（已加入 `DarkTheme.xaml` / `LightTheme.xaml`）
| Token | 用途 | 深色 | 浅色 |
|---|---|---|---|
| `InfoBackground` / `InfoBorder` / `InfoText` | 问题面板/信息区 | 深青蓝低饱和 | `#EFF6FF` / `#BFDBFE` / `#1E40AF` |
| `WarningBackground` / `WarningBorder` / `WarningText` | 审批面板/plan-review 卡/错误条 | 深琥珀低饱和 | `#FFFBEB` / `#FDE68A` / `#92400E` |
| `DangerBackground` | 错误条底 | `#2B1616` | `#FEF2F2` |
| `HighlightBackground` | 搜索命中高亮 | `#3A3414` | `#FEF08A` |
| `CardSurface` / `CardBorder` | 悬停卡片/内容卡片 | `#1B2121` / `#2A3333` | `#FFFFFF` / `#E2E8E8` |
| `HoverCardBackground` | 会话悬停态 | `#232B2B` | `#F1F5F5` |

### 10.3 已收敛位置（2026-08-21）
- `MainWindow.xaml`：问题面板、plan-review 卡、审批面板、错误条、搜索高亮、作品日志区、会话悬停卡 → 全部改用语义/`Surface` 令牌。
- `InputDialog.xaml` / `RenameDialog.xaml`：窗体 `Background`/`Foreground` 由 `White`/`Black` 改为 `Surface1`/`TextPrimary`。
- `HtmlPreviewWindow.cs`：`DefaultBackgroundColor` 改 `Transparent`、窗体 `Background` 改 `Surface1`；`WrapHtml` 注入**主题感知 CSS**（按 `ThemeSettings.Theme` 决定 body/code/link 配色）。
- `SettingsWindow.xaml`：已声明 `Background="{DynamicResource Surface1}"`，本次保留；加诊断日志确认 `Surface1` 运行时解析（见 `06` 待复核项）。

### 10.4 检查手段（建议）
- 提交前 grep：`grep -rnE '#[0-9A-Fa-f]{6}' --include=*.xaml` 与 `Brushes\.(White|Black|...)` 应为空（语义令牌外的纯色除外，如焦点环固定品牌色可豁免但需注释理由）。
- 验收方式（见 `04` §3）：切换深/浅主题各截图，确认无"该深未深/该浅未浅"漏色区。

### 10.5 系统性修复（2026-08-21 U1 第二轮根治）
前几轮"逐点灭火"漏色的根因是 **WPF 默认主题透出**：`TreeView`/`ListBox`/`ItemsControl`/`ScrollViewer`/`Window` 这些容器在 .NET 8 默认走系统 AERO 样式，自身会绘制浅色背景，即便父 Background 已设深色。**根治策略**（已落地 `Controls.xaml`）：
- `Style TargetType="Window"` 设 `Background="{DynamicResource Surface1}"`——所有未显式 Background 的子容器透上来都是 Surface1（深色）。
- `Style TargetType="TreeView/ListBox/ListView/ItemsControl/ScrollViewer` 显式设 `"Transparent"`——避免 WPF 自身画 Aero/Control 浅色。
- 之后任何"漏色"问题只要截屏定位，都能用 4 类方法诊断：(a) `Window` 是否被容器覆盖；(b) `ItemsControl` 是否漏 `Background="Transparent"`；(c) 自定义模板是否漏刷背景；(d) `WebView2` 等外部宿主。
**禁止再逐点补漏**：每发现一处漏色必先确认是否违反以上四条；如新增容器类型（如 Expander/DataGrid）需同步在 `Controls.xaml` 加默认样式。
